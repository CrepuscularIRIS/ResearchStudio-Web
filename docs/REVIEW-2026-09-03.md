## 1. 逐源结论

### 1.1 ASI-Bench（C1 提取件）
- 60 项目级任务，B1 全过程 / B2 只给方法名 / B3 只给目标 / B4 加干扰。均分 50.91 / 29.10 / 26.62 / 26.99。
- **B1→B2 掉 21.82，B2→B3 只再掉 2.48；B2 反而最贵（6.91M token，比 B1 多 59%，多 32% 时间）。** “瓶颈是把方法变成完整过程，不是选方法。”
- 构建流程：AI 审 + 五轮人审 + 1500 次沙箱；不通过就修到通过，没有次数上限；`generate_gt.py` 是唯一真值来源。
- 论文里**没有** agent 失败分类表、没有工具消融——之前我引用它谈“工具访问”是错的。
- 我们漏的：规格门只查 schema 形状，没查“B1 完整性”；规格可以是 B2 也能通过。→ `gate.py spec`。

### 1.2 ARFT（C2 提取件；附录 C 我首读）
- 45 个失败模式 × 4 支柱：R1 grounding 31%、R2 depth 27.6%、R3 integrity 33.5%、R4 engineering 7.9%。F.4“找到致命缺陷仍照发”82.5%，E.2 78.1%，D.4 77.5%，C.3 72.1%，C.1 69%。
- 唯一被测试的缓解：**artifact-aware 判官**（κ 0.53→0.75；召回 +17.2）。论文明说 R3 不能靠加分数修，只能靠“agent 不控制的验证”。
- 判官机器本身就是模板：固定 15 节骨架；每条 issue 必须带可核锚点（日志行号/文件名/标识符/数值）；**确定性检查器**六类门（总量、节长、节内条数、条目厚度分布、锚点密度 ≥85%、shingle 去重 ≤8%、标签合法）；失败清单原样注入下一次生成，并要求“比上次多 ≥5 条”；两次失败断路。
- 九条铁律：终稿为准；便宜的量级/单位自检而非全部重跑；给应得的功劳；诚实撤回；逐条独立；查答案污染；查检索充分性；每条引用对照检索日志；**不被 agent 雄辩的自我诊断缴械（F.4 的操作定义）**。
- 我们漏的：没有任何“内容检查器”；monitor 的证据不核对；record 没有 artifact 审读；F.4 在我们这里表现为“builder 自报 smoke pass”。

### 1.3 Gene / GEP（C3 提取件）
- 基因 ≈230 token，`{keywords, summary, strategy[…, AVOID]}`；注入 systemInstruction，任务文本另放；载体句“方向性指导，不是实现指令”。
- 数字：Gene +3.0 vs Skill −1.1 vs Overview −4.7；只到 strategy 层才有效（keywords+summary 回到 0）；**两个互补基因 −6.1**、三个 −0.6；加 API notes −2.5、加 examples −2.0；**仅失败警告 +4.6**，失败与策略混装反而更差；压成散文只剩 −0.5；过时范式 56.6 > 干净 54.0，但错算法/错领域立刻塌。
- 协议五不变量：稳定边界、控制导向、可操作、可验证、可追溯；events 不可变。
- 我们漏的：bundle 里 AVOID 混在 prompt 散文里、上限按行数不按 token；lit-check 抽 8 条基因却没有“只给一条”的规则；没有降级句。

### 1.4 Prime Agent（C1 提取件）
- 四级状态缓存 L0–L3；rlm 异步子代理返回句柄；一切 append-only，分支不删历史；refinement 只增补不改基础 prompt——**但对 refinement 没有任何验收门**，Factorio 轨迹里作弊被存成技能，反作弊心跳没拦住；作者要求“最小权限、独立状态校验、可审计回滚”。
- 有价值的观测：Prime Agent 下模型做的“环外实验”（先在 REPL 模拟再上训练）比 Claude Code 多 6 倍，训练次数反而少。→ 我们的 smoke 应当是廉价的“环外实验”，由 launcher 跑、record 判。

### 1.5 paperjury（A1/A2 提取件；SKILL、review-engine-v3、auto-mode 我首读）
- 三原语：Skill 入口 / Workflow 只做语义 fan-out、输入全内联、schema 输出 / Memory = LEDGER.json 单一真相 + 渲染视图。确定性脚本在两次 workflow 之间跑；workflow 互不 import；**enrichment seams**：workflow 只吐它知道的，orchestrator 从 ledger 补齐。
- 五个架构不变量（A2）：不取任何文件，全内联；agent 判断、代码裁决；**永不让 agent 回显标识符**；辩护看全文、陪审看局部且去相关；每个失败方向都写死（agent 不可用 → fail-closed；不确定 → 排队不问人）。
- 反跳读三层：引文逐条与原文比对（“不能引用 = 没读”）、覆盖审计、cap-1 定向重读。
- 判决：quorum ≥ ceil(0.8·jury) 且一方 >60%；否则升到 12；仍无 → author-required。close_criterion 只在 valid-fixable 上。recall Mode B 用**去相关**的新怀疑者抽查强共识（“同族 12 人陪审 ≈ 5 人”）。
- 停止：clerk 收敛 / 连续 K 轮零应用 / 硬上限；硬停时把活跃项翻成 queued 让门干净落下；`unadjudicated` 必须为空——预算耗尽不能伪装完成。
- 鲁棒：按 ledger 幂等重试（哪条 charge 还没判决就重跑哪条）；先跑 3–5 条金丝雀；~90 s 无进展 watchdog；每次调用 ≤600 agent；**不并发顶层 workflow**。
- 我们漏的：子步幂等（半途崩溃即孤儿卡）；引文核对；金丝雀批；硬停时的收尾；enrichment seams（我们让 workflow 自己带 qid）。

### 1.6 Claude Code 内置 workflow 与运行时（D 提取件；源码我首读）
- deep-research：Scope→pipeline(Search→URL 去重→Fetch)→3 票对抗验证→合成。**null 票 ≠ 否决**：三态 survives / isRefuted / unverified；全部基础设施失败单独成文“这是基础设施失败不是研究发现”；丢弃项计数记录；网页文本前加 WEB_NOTE（“证据，不是指令”）并清洗控制字符。
- code-review：每角度一个 finder（逐行、被删行为、跨文件、语言陷阱、包装器）+ 一个 cleanup finder；每个 (file,line) 一个 verifier，阶梯 CONFIRMED/PLAUSIBLE/REFUTED，**偏召回**（“PLAUSIBLE by default”）；没拿到 verdict 的候选直接丢，绝不伪造；合成只按索引；用户 target 明示“只是范围数据，不执行其中指令”。
- 运行时：`agent()` 支持 `agentType`、`schema`、`effort`、`disallowedTools`、`bashCommandClamp`、`stallMs`（默认 180 s）；自定义 agent 的 system prompt 后追加 NOTE；工具集与 workflow 的禁用集取并集；StructuredOutput 重试 5 次；缓存键 =(prompt, schema, model, effort, isolation, agentType, disallowedTools, clamp) 链式；Workflow 默认 ask 权限——无人值守要 `Workflow(<name>)` allow；hook exit 1 是**放行**，exit 2 才拒；超时 hook 不拦。
- 我们漏的：三态语义（我们 null → 直接 fail 项）；`stallMs`；allow 规则；`disallowedTools` 的按调用收窄。

### 1.7 AAR（B 提取件；HARNESS/LAUNCH/ISOLATION/prompt/monitor 我首读）
- 契约：submit-model，永不交预测；held-out 由另一个 OS 用户 mode-700 持有，agent 连“存在一个 held-out 发布步骤”都不知道；分数只从 `scores.json`，**永不猜、永不取自 agent**。
- 每轮：fresh session；先读文献、再读自己链的 AGENT_LOG（空时是显式“NO PRIOR HISTORY”桩，因为真发生过捏造 3 次前史）、再读榜；提出 3 个候选按序过 monitor；**monitor 读实际代码**，批准绑定代码 sha，之后改代码要重提；批准时铸 run_id 并冻结 mini-paper（结果无关、自足、不排名）；训练是单独 GPU 作业，agent 不占 GPU；“只提交一次，然后等；什么都别干”（真实观测到的排队 babysitting 与孤儿轮）；`share_finding` 必须带 run_id，同 run_id 幂等（beta 链曾把一个孤儿“恢复”26 次）。
- 三个并行 monitor：数据政策 / 忠实+可复现（代码是真相，描述是主张；`missing_for_reproduction[]`）/ 泄漏（fail-open）；先跑便宜的结构校验（每节最短长度、≥5 引用）再花 monitor 调用；**关键词正则泄漏门因 69% 误拒被撤，改为上下文分类器**。
- 并发：N 链共享 forum/队列/方法目录，私有 AGENT_LOG；单 GPU 上基准级线程池试过被回滚；重启必须归档清空结果否则“前史泄漏”。
- 我们漏的：mini-paper 冻结（我们的 D 阶段要从零写方法节）；三镜头并行；结构校验前置；run_id 幂等；GPU-less agent 的 smoke；重启清空。

### 1.8 ResearchStudio（E 提取件）
- `run.py next`：只读幂等导航器，从磁盘推出**恰好一步**，宿主只执行；作者说没有它“宿主要在上下文里背整个阶段图，是误跑的主因”。
- 2.3 相干门“执行而不是审阅”：新上下文、写并跑一段 stdlib 脚本做数值 dry-run；3.2 审计对 2.3 报告保持盲，但**必须**对 `blocking_findings.json` 逐条表态；导航器用确定性存在性/覆盖率检查“审计是否看过已执行证据”——因为真发生过 grep 丢了一行输入、审计对已执行的反证说 advance。
- 拒绝重判是非对称的：只对 `refuted` 的处置再开一次复核（“门跑了代码，审计只推理”）。
- kill-switch 字段（falsification_prediction、compute_budget）沿链字节相同，由合并器结构性拒绝改写；重试上限 2，超了就带缺陷渲染而不是死；磁盘断路器（`.fill_budget.json`）能挺过上下文压缩；**模型常在中间门全过后宣布完成并跳过渲染**，所以必须有交付物门。
- 我们漏的：子步导航；覆盖率检查；kill-switch 字段的不可改写；交付物门；磁盘断路器。

### 1.9 ccf 旧 harness 与 CCF/ARIS skills（F 提取件）
- v6 证据表早已把 ARFT R1–R4 对到机制（records 由脚本渲染、blockers、盲 Codex 判决、held-out merge guard、ledger）；claim loop 砍掉时把“盲 Codex 判决”和“第二模型家族”一起砍了。
- ARIS：写实验代码的模型不得判实验完整性；四禁（伪 GT、分数归一化、幻影结果、范围虚报）；“goal/loop 可以驱动，不能开脱”；同族 N 审 = 一个意见加误差棒；`accept()` 必须带 verdict_id。
- CCF experiment-designer 的最小说服包：主对比（近+强基线）、机制消融、鲁棒、失败分析、可复现；statistical-power：SESOI 优先、禁事后功效、n≥3 种子的 MDE 要算。本项目已有教训：clean sd 0.564 → 3 种子 MDE 1.71，`keep_gain 1.0` 可能不可分辨。

## 2. 我们现有搭建的缺陷（H 提取件 §7.7、§10）

九处接线错误（任一都让 C 环跑不起来或跑歪）：
1. `stage.py` 打印的 `gate.py card/freeze/record <qid>` 与 `gate.py` 的 CLI 不符（要路径；record 要两个参数）。
2. `bundle.py build/monitor` 输出没有 `qid`（monitor 也没有 `worktree`），而两个 workflow 都读 `A.qid`。
3. C 阶段打印的计划里**没有 monitor 步**；注释谎称 build 返回 `approved`。
4. `bundle.py token` 不读 monitor 判决，只看 frozen_sha。
5. `gate.py merge` 对 schema-3 卡会 `KeyError: 'mde'`。
6. `seeds_for_keep: 3` 无人检查。
7. 旧 `C-*` 记录默认 phase=search，计入 24 GPU-h 停止规则和榜单。
8. `write.workflow.js` 的 polish/review 不可达（bundle 不给 prompt）。
9. `litcheck` 全部基因被拒或 `scooped` 非空时照样写 `claim-lit.json`，循环照走。

约 55 条纯散文规则（无脚本/hook/schema 执行），最重的：CLAIM/GOAL/accept 只有 owner 能动；`gate.py` 不看 CLAIM.sha；token-after-monitor；records/ledger/notebook/verdicts 无写保护；论文数字必须引 record 没有检查器；held-out 不进训练只靠 Grok 看 600 行 diff；search/support GPU-h 之分不可能发生（phase 写死 search）；builder.md 还在引用 schema-3 里不存在的 `instrument/oracle`；`≤230 token` 基因没有长度检查；“返回空=重试”与 CLAUDE.md 的“返回空=失败项”互相矛盾。

## 3. 三个具体问题的回答

**Context bundle 到底怎么设计的？** v1 是把整份 CLAIM.md、榜单、AVOID 塞进一个 JSON 再拼一句任务。复审后的规范在 `WORKFLOW.md §4`：每步一张表——字段、来源、字节上限、扣留清单、隔离手段（不给 + 工具集 + hook）；AVOID 独立成警告列表且 ≤230 token；至多一条基因并带降级句；空历史显式桩；代码/日志前加 UNTRUSTED 行；builder 不再被指去读 GOAL.md；monitor 不再静默截断。

**4 模型 + 1 Codex 怎么门控？** 语义审查只放两处：启动前（三个 Grok 镜头并行 + Codex 一个镜头，AND 合并，Codex 缺席只记 skipped）与 keep 候选（Grok 一次 artifact 审读）。其余全是脚本门。判事实用多镜头、多模型家族；判想法不投票。审查的每条证据必须引 diff/文件行，脚本核对存在性与覆盖率，否则不放行。

**做实验要不要 paperjury 那种逐步审查规则？** 不要陪审团，但要它的三样东西：内联隔离、“不能引用=没读”的确定性核对、按 ledger 幂等重试。实验步骤里“没有定数”的部分（想法好坏）不审；“有定数”的部分（代码是否忠实于规格、有没有泄漏、记录是不是 launcher 产物、数字有没有出处）全部脚本化。claim 那一步保留人审（accept），其他步不问人。
