# research-harness 0.4 — the V9 harness

An unattended research loop for [Claude Code](https://docs.claude.com/en/docs/claude-code/overview): **one Brain workflow** turns a code
repository plus a FROZEN goal into idea cards, an evidence plan and machine-checkable B1 specs; **a main-window skill chain** builds, launches,
judges and reviews each experiment block; **one navigator script** (`next.py`) says what the single next step is, and `/exp-auto` is the loop.
No dag, no bus, no hooks, no custom agent types.

```
Brain (Workflow, ~1.5 h, k runs)        repo + FROZEN → intake → ResearchStudio idea-spark Phase 0–4 verbatim → evidence plan → B1 specs → ranking
Experiment (main window, skills)       /exp-next → /exp-critic spec → /exp-build → /exp-critic code → /exp-launch → WAIT → /exp-verdict → /exp-critic process
Navigator                              next.py <run_root> --json   ·   /exp-auto <run_root>   ·   /loop 10m /exp-auto <run_root> while a GPU unit runs
Back-channel                           failure card → backup run → Brain re-trigger with args.negative_anchors (retrigger.py, capped) → BLOCKED
```

0.4 replaces everything in 0.3 (the research / experiment / paper workflows and `dag.py`). Nothing of those remains; git history has them.

## Brain — `workflows/brain.workflow.js` (generated; never edit)

One self-contained Workflow script (~430 KB, 41 verbatim prompt/reference files inlined) generated by `scripts/brain_src/gen_brain.py` from
`brain.logic.js` + `refs/`. It runs ResearchStudio's `run.py next` navigator and routes every emitted prompt to a seat:

| seat | step | model / effort | tools |
|---|---|---|---|
| intake | Phase −1 repository intake (10 intake fields + substrate.md) | GLM / medium | read-only repo |
| tagging | 0c pattern tagging (parallel shards) | GLM / low | read/write |
| phase1 | bottleneck + method lineage (+ CCF relation map, evidence quotes checked mechanically) | Opus / high | read/write |
| ideate / generate | 2.1 + 2.2 gap × pattern → candidate (substrate premise; run diversity for k > 1) | Opus / high | read/write |
| coherence | 2.3 dry-run trace: T1 formalise · T2 executed numeric dry-run · T3 probes · T4 claim grading · T5 independent naive baseline | **GPT-6 Astra** / high, fallback Opus | python only |
| audit / recheck / reaudit | 3.2 five checks (+ CCF strict review, ARFT codes, FROZEN scope check, threat quote checked) | K3 / high·medium | read/write |
| revise | 3.3 patch (named fields only) | Opus / high | read/write |
| fill / derive / impl | 4b card (ARIS key-equations discipline) · plain register · 4.1.5 implementability | Opus / GLM / GLM | read/write |
| evidence | Phase 5 evidence plan (CCF evidence design, ARIS experiment plan + ablation planner, Lehr MDE) | Opus / high | read/write |
| spec | Phase 6 B1 specs in machine form (`verdict_rule.keep_if_all`, arms, negative control, ASI `gates[]`) | Opus / high | read-only repo |
| rank | CCF rubric + calibration + expert panel; deterministic recomputation | Opus / high | read/write |

Deterministic checks between seats (quote checks, `plan_check`, `spec_check`, `rank_check`, RS validate + regression_check, placeholder scan)
each get one repair. Every seat pins a model id **and** an effort; unknown ids are served silently by the session model on the official API, so
launch the Brain from a session whose ids resolve (a LiteLLM proxy: `claude-opus-5`, `glm-5.3[1m]`, `k3-256k`, `gpt-6-astra`; override with
`args.models`). `args.negative_anchors` (failure cards) reach Phase 1, ideate and 3.2 only.

## Experiment — seven skills, six scripts (`skills/`, `scripts/exp/`)

| skill | script | what it does |
|---|---|---|
| exp-next | `precheck.py` | claim the next block of the top-ranked run: Brain's own `spec_check` re-run, budget, decision-field seal (`spec.sha`), canary from `instruments/README.md` |
| exp-critic spec / code / process | `critic.py` + `critic.md` + `anchor_check.py` | Grok CLI, read-only (`--permission-mode plan`), paths only, never summaries; `critic.md` is assembled verbatim from ARIS / ASI-Bench / ARFT / V8 texts; findings need a verifiable anchor; zero-discretion routing (pass · fix cap 2+1 · L2 · L3 · L4 needs a second vote) |
| exp-build | refs (V8 PREREG / METHOD-COMPLETE / SELF_CHECK / PITFALLS / OBSTACLE, verbatim) | implement one block in a worktree to `gate_passed` |
| exp-launch | `launch.sh` | zero-tolerance greps + `spec.gates` over the diff, GPU pre-flight, `systemd-run` + `launch_wrap.sh` (smoke canary → seeds, watchdog, ETA 2×; exit 3/4/5 are never verdicts) |
| exp-verdict | `verdict.py` | the numeric gate, reading result files only: exit code · seal · gates · `keep_if_all` · CI · too-good · negative control → L3 |
| exp-handoff | — | six-section handoff file, memories, fresh session (never compact) |
| exp-auto | `next.py`, `retrigger.py`, `report.py`, `failure_card.py` | the loop; the ladder after a failure card; result tables from `verdict.json` only |

## Install

```
claude plugin marketplace add CrepuscularIRIS/research-harness
claude plugin install research-harness
/research-harness:init --slug <topic> --repo </abs/path/to/the/code/repo>     # in the harness project root
```

`init` copies the workflow, the skills, `.research/tools/{exp,brain_src,launch_wrap.sh}`, `.research/tests` and `docs/refs` (the prompt bank)
into the project, and writes once: `.research/GOAL.md`, `.research/instruments/README.md`, `.research/anomalies.md`, `.claude/CLAUDE.md`,
`.research/research/ideaspark/<topic>/args.json`. Then:

1. Fill `.research/GOAL.md` `## FROZEN`; paste the block into `args.json` → `goal`; fill `dataset`, `venue`.
2. Put the clean canary number into `.research/instruments/README.md` (`CANARY_EXPECTED=<n> --setenv=CANARY_TOL=<n>`).
3. `python3 -m pytest .research/tests -q` (20 tests, no model calls).
4. From a session whose model ids resolve: `/exp-auto .research/research/ideaspark/<topic>`.

## External dependencies

- A proxy that serves the non-Anthropic ids (the author's LiteLLM :4001 → Zhipu GLM, Kimi K3, Codex-OAuth GPT-6 Astra). Official-API-only:
  set `args.models` to `claude-opus-5` / `claude-sonnet-5` and expect the whole Brain on Anthropic models.
- Grok CLI (`grok`, the official plugin's binary) for the three reviews; absent Grok is `critic_failed`, never a verdict (fail-closed).
- `systemd --user` and `nvidia-smi` for launches.
- `docs/refs/` vendors verbatim third-party texts (ResearchStudio idea_spark, CCF, ARIS, ASI-Bench, ARFT); their licences apply.

## Tests

`bash tests/selftest.sh` installs the harness into a scratch directory and runs the 20 tests there (pytest + node). The suites are sandboxed
(`EXP_SANDBOX`), carry their own canary README and a real m158 verdict fixture, and byte-check that the committed workflow equals what the
generator produces and that every inlined prompt equals its source file.

## Not yet exercised live

Grok's real call (only dry-run tested; the invocation equals the official plugin's), `spec.arms[].eval_type` (warn, not enforced), the K3 second
vote for L4, and one end-to-end run of the chain. The design documents under `docs/` record every decision and the audits behind them.
